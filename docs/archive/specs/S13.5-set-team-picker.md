## Goal
Allow the organizer to select which 2 of 3+ teams will play in the current set, then proceed to the scoreboard (S14) for live score entry. This screen appears only when a match has 3+ teams configured; matches with exactly 2 teams skip directly to the scoreboard.

## Route
Implemented as the **conditional initial render** of `app/matches/[id]/scoreboard.tsx` — **not** a separate route.

**Conditional rendering logic:**
- When the user navigates to `/matches/[id]/scoreboard` with route params `{ id, setNumber, bestOf }`
- If `teams.length >= 3 && selectedTeamIds.length < 2`:
  - Render S13.5 team picker UI
- Once user selects exactly 2 teams and taps "Começar partida":
  - Call mutation to write selection to backend
  - On success, state updates; conditional re-renders to S14 scoreboard (same component, same route)

**Navigation flow:**
- **From**: S13 (In-Game Teams) — user taps "Confirmar" or "Começar os times"
- **If** `teams.length === 2`: skip S13.5, go directly to S14 scoreboard
- **If** `teams.length >= 3`: show S13.5; after selecting 2 teams → S14 scoreboard

**Route params from S13:**
- `id: string` — match id (Expo Router dynamic segment)
- `setNumber: number` — current set number (1, 2, 3, etc.)
- `bestOf: number` — best-of series (e.g. 3 for "melhor de 3")

## Backend dependencies

**F1.3** (read teams) — already loaded by S13; provides:
- `teams: Team[]` array with `{ id, name, players: Player[] }`
- Previous set results (if any) for winner highlight

**F1.4** (write set selection) — `POST /api/v1/matches/{id}/sets/{setNumber}/select-teams` (or equivalent)
- Request body: `{ teamIds: [string, string] }` (array of 2 team IDs)
- Response: confirmation or error
- **Posture**: Per S13 convention, this is **fully mocked** this iteration (backend F1.4 path not yet aligned in quadra-api)
  - Hook signature and payload shape are final
  - `mutationFn` is stubbed; marked `// MOCK:` with `// TODO(real-api):` pointing at F1.4
  - Replaceable behind unchanged hook signatures once backend lands

## Implementation notes

### Key architectural decisions

1. **Not a separate route** — S13.5 lives as a conditional initial render within the S14 scoreboard component (`app/matches/[id]/scoreboard.tsx`).
   - Rationale: The set picker is a pre-match state, not a full screen in its own right. Once 2 teams are selected, the same URL immediately transitions to live scoring. Keeping them in one component file (one route) simplifies conditional logic and avoids registering redundant routes.
   - Pattern: `if (teams.length >= 3 && selectedTeamIds.length < 2) then <Picker /> else <Board />`

2. **Team color mapping** — the reference PNG shows color-coded team badges:
   - Time Azul (blue) → use `bg-primary`
   - Time Lima (lime) → use `bg-accent`
   - Time Laranja (orange) → use `bg-tertiary`
   - Implement `getTeamBgColor(teamId)` helper that maps team index or team name to a Tailwind color class
   - Define in component or extract to `src/features/matches/lib/teamColors.ts` if reused by S13

3. **Previous set winner highlight** — the pill "Venceu o set e continua em quadra" is shown **only** if that team won the previous set.
   - Read `previousSetWinnerId` from match data (assumption: backend includes this in the match detail response)
   - If not available in API, mock it for this iteration

4. **Team selection deselection behavior**:
   - Tapping a team when 0 selected: select it (add to array)
   - Tapping a team when 1 selected: select it if it's different (add to array)
   - Tapping the 2nd selected team: deselect it (remove from array)
   - Tapping an unselected team when 2 already selected: no-op (disable the Pressable)

5. **Mocking strategy** — follow S13's `// MOCK:` pattern:
   ```typescript
   // src/features/matches/api/selectTeamsForSet.ts
   export function useSelectTeamsForSet(matchId: string, setNumber: number) {
     return useMutation({
       mutationFn: async (teamIds: [string, string]) => {
         // MOCK: backend F1.4 path not yet aligned
         await new Promise(resolve => setTimeout(resolve, 400));
         return { success: true, setNumber };
         // TODO(real-api): swap with real POST /api/v1/matches/{matchId}/sets/{setNumber}/select-teams
       },
     });
   }
   ```

6. **Team organizer fallback** — if team object includes a `leader` or `organizer` field with `@handle`, show it; otherwise show "N jogadores" only.

7. **Accessibility**:
   - Each team row: `accessibilityRole="radio"` + `accessibilityState={{ selected }}`
   - Pairing pill: display-only (no role)
   - "Começar partida": standard button role (inherited from `Button` component)
   - Live region for "X times remaining" message uses `accessibilityLiveRegion="polite"`

8. **Polish (optional)** — the footer pairing pill animates in smoothly once 2 teams are selected
   - If using `react-native-reanimated` (already in stack): fade + scale transition
   - If skipping animation: simple opacity change is fine for MVP

### Common pitfalls

- **Conditional logic inversion**: If checking `showSetPicker`, ensure it's `teams.length >= 3 && selectedTeamIds.length < 2`, not `< 3`.
- **Team color clash**: Three teams may need distinct colors; use `primary` (blue), `accent` (lime), `tertiary` (orange) in priority order. A 4th team (unlikely in MVP) would wrap to `quaternary` (violet).
- **Mutation side effects**: After `selectTeamsForSet` succeeds, do **not** reset `selectedTeamIds`. Keep them in state so if the user navigates back to S13 and forward again, the selection persists in session.
